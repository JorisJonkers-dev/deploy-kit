\subsection{Concrete Syntax and Constraints}
\label{sec:constraints}

The source language has a textual syntax and OCL constraints that reject
invalid models.

\subsubsection{The Concrete Syntax}

Authors use the YAML subset found in the existing configuration. Two Xtext
grammars define this syntax: one for \texttt{platform.intent.yml} and one for
\texttt{*.project.yml} (Section~\ref{sec:grammarfirst}). Both use source
metamodel classes. YAML keys may appear in any order.

A route refers to a declared process and named port. An undeclared process
produces a reference error, \texttt{E\_UNKNOWN\_PROCESS}. Handover project
identifiers remain strings checked by an invariant because projects are
separate documents.

\subsubsection{The Constraints}

Complete OCL defines 36 invariants and 9 \texttt{def} helpers for the source
metamodel. The invariants use 28 distinct codes. Three occur on multiple
context classes.

\textbf{Each invariant has its diagnostic code as its name and the rejected
object's class as its context.} Its diagnostic identifies the rule and the
object to fix. Table~\ref{tab:constraints-sample} samples the scopes.
Appendix~\ref{sec:allconstraints} lists all 28 codes.

\begin{table}[!htbp]
\centering
\footnotesize
\begin{tabular}{>{\raggedright\arraybackslash}p{0.39\linewidth}>{\raggedright\arraybackslash}p{0.15\linewidth}>{\raggedright\arraybackslash}p{0.38\linewidth}}
\hline
\textbf{Code} & \textbf{Context} & \textbf{What it rejects} \\
\hline
E\_CUTOVER\_UNHONOURABLE & Process & One object: a \texttt{continuous} process whose storage cannot attach to the second copy a blue/green switch starts. \\
E\_RELEASE\_UNIT\_MIXED\_CUTOVER & Application & One document: an application whose processes have different \texttt{cutover} values, although it switches as one unit. \\
E\_NO\_FORWARD\_AUTH\_ENDPOINT & Tier & The platform document: a tier that serves authenticated visitors but declares no endpoint to check whether a visitor may enter. \\
E\_NO\_TIER\_FOR\_AUDIENCE & Exposure, Route & Across documents: an audience no edge tier in the platform document serves. \\
\hline
\end{tabular}
\caption{One Constraint for Each Scope}
\label{tab:constraints-sample}
\end{table}

Ten project-context constraints use another document: the platform document or
a database provider's project file. The invariant's context identifies the
object to fix. \texttt{allInstances()} searches the loaded resource set. Guards
skip cross-document checks when a project file is loaded alone
(Example~\ref{lst:notier}).

\begin{lstlisting}[style=report, language=ocl, basicstyle=\footnotesize\ttfamily,
                   caption={E\_NO\_TIER\_FOR\_AUDIENCE, with a guard for a project file loaded alone},
                   label={lst:notier}]
context Exposure
    inv E_NO_TIER_FOR_AUDIENCE:
        Tier.allInstances()->notEmpty() implies
            Tier.allInstances()->exists(audiences->includes(self.audience))
\end{lstlisting}

EMF reads an unset enumeration as its first literal. Optional enumerations use
an unwritable \texttt{absent} literal, which invariants test instead of
\texttt{null}. Constraints over every project document at once, such as unique
application identifiers, are not part of the OCL constraints.

\subsection{Implementation in EMF}
\label{sec:implementation}

The artefacts are Eclipse plug-in projects in \texttt{implementation/emf/},
built by Maven and Tycho on JDK~21. Three projects make up Task 1.

\begin{itemize}
  \item \texttt{metamodel} holds the two \texttt{.ecore} files, their
    \texttt{.genmodel} files and the Complete OCL file. The build generates the
    metamodels' Java classes from the genmodels.
  \item \texttt{syntax} holds the two Xtext grammars and the generated editor.
    The editor marks an OCL violation on the line of the authored file that
    causes it.
  \item \texttt{cli} holds a program that reads a set of authored files and
    writes either the parsed model or the \emph{diagnostics} that reject it. A
    diagnostic holds the code, the file and the path of the rejected object in
    that file.
\end{itemize}

The program checks in three steps and stops after the first step that finds an
error. It parses each file, validates each parsed model against the OCL
constraints, and then validates the files of a set together, for the
constraints across documents. It also writes each parsed model as XMI, named
after its file: \texttt{notes.project.yml} becomes \texttt{notes.project.xmi}.

\texttt{./mvnw verify} in \texttt{implementation/emf} builds the projects and
runs the tests of Section~\ref{sec:tests}. The projects \texttt{resolve} and
\texttt{render} contain the start of Tasks 2 and 3.

The hand-in's \texttt{task-1-metamodelling} project holds the metamodels and
every model as XMI, so the models can be inspected without a build
(Appendix~\ref{sec:handin}). Its copy of \texttt{project-intent.ecore} embeds
the OCL invariants, so Eclipse's Validate reports them directly.
