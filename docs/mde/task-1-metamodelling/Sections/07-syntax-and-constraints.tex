\section{Concrete Syntax and Constraints}
\label{sec:constraints}

The source language has a textual syntax and OCL constraints that reject
invalid models.

\subsection{The Concrete Syntax}

Authors use the YAML subset found in the existing configuration. Two Xtext
grammars define this syntax: one for \texttt{platform.intent.yml} and one for
\texttt{*.project.yml} (Section~\ref{sec:grammarfirst}). Both use source
metamodel classes. YAML keys may appear in any order.

A route refers to a declared process and named port. An undeclared process
produces a reference error, \texttt{E\_UNKNOWN\_PROCESS}. Handover project
identifiers remain strings checked by an invariant because projects are
separate documents.

\subsection{The Constraints}

Complete OCL defines 36 invariants and 9 \texttt{def} helpers for the source
metamodel. The invariants use 28 distinct codes. Three occur on multiple
context classes.

\textbf{Each invariant has its diagnostic code as its name and the rejected
object's class as its context.} Its diagnostic identifies the rule and the
object to fix. Table~\ref{tab:constraints-sample} samples the scopes.
Appendix~\ref{sec:allconstraints} lists all 28 codes.

\hline
\textbf{Code} & \textbf{Context} & \textbf{What it rejects} \\
\hline
E\_CUTOVER\_UNHONOURABLE & Process & One object: a \texttt{continuous} process whose storage cannot attach to the second copy a blue/green switch starts. \\

Ten project-context constraints use another document: the platform document or
a database provider's project file. The invariant's context identifies the
object to fix. \texttt{allInstances()} searches the loaded resource set. Guards
skip cross-document checks when a project file is loaded alone
(Example~\ref{lst:notier}).

\begin{lstlisting}[style=report, language=ocl, basicstyle=\footnotesize\ttfamily,
                   caption={E\_NO\_TIER\_FOR\_AUDIENCE, with a guard for a project file loaded alone},
                   label={lst:notier}]
context Exposure
    inv E_NO_TIER_FOR_AUDIENCE:
        Tier.allInstances()->notEmpty() implies
            Tier.allInstances()->exists(audiences->includes(self.audience))
\end{lstlisting}

EMF reads an unset enumeration as its first literal. Optional enumerations use
an unwritable \texttt{absent} literal, which invariants test instead of
\texttt{null}. Constraints over every project document at once, such as unique
application identifiers, are not part of the OCL constraints.

\subsection{Rejected Example Models}

The archive has 33 rejected cases: 18 single project files and 15 sets of a
platform and project document. Together they cover all 28 invariant codes and
four unresolved-reference codes. The files in each set are valid separately.
For invariant violations, Eclipse Validate reports the invariant's name as the
code (Appendix~\ref{sec:appendix-refused}).
