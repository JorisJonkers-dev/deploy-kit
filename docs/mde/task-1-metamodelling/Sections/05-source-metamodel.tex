\section{The Source Metamodel}
\label{sec:sourcemetamodel}

The source metamodel, \texttt{metamodels/project-intent.ecore} in the archive,
defines two kinds of document. A \emph{project} document,
written by the owner of a group of applications, states what those applications
need. One \emph{platform} document states what the cluster offers, including
every shared value (Section~\ref{sec:sharedvalues}).

\subsection{The Project Document}

An application declares a migration if and only if it uses a database, and each
project's one database is migrated by one application. The abstract class
\texttt{Migration} has three subclasses. The platform's runner applies the
changelog of a \texttt{ManagedMigration} before any new version starts. A
\texttt{SelfMigration}, which a third-party image needs, leaves the schema to
the image. A \texttt{NoMigration} leaves it to another application.

A process's \texttt{cutover} states whether it must keep serving during an
upgrade. With \texttt{continuous}, the new version starts beside the old one and
receives traffic only after every process of the application passes its metric
checks. Such a switch is called \emph{blue/green}. With \texttt{interrupted}, the
old version stops first. A process's \texttt{lifecycle} is \texttt{application},
\texttt{job} or \texttt{prepare}. A \emph{prepare process} is irreversible
one-off setup, such as a seed, that runs after the migration and before the new
version starts, and serves no traffic.

An exposure belongs to the application, because one hostname serves several
processes, selected by path. A route and a dependency both refer to a
\texttt{Surface} by name: a route to a process of its own application, and a
dependency to a process of another application.

\subsection{The Platform Document}

The platform document holds the facts and policies that no single application
may set. Each platform value describes a fact, such as whether the cluster
encrypts secrets at rest, not the setting that implements it
(Section~\ref{sec:naming}). Two platform values refer by name to applications
that a project document declares: a tier's proxy and the delivery machinery.
Constraints use two facts. Without encryption at rest, every secret delivery is
rejected. A volume or process whose durability class or engine has
no policy is rejected (Section~\ref{sec:constraints}).

\subsection{Enumerations}

Each attribute with a fixed set of values has an enumeration type. In
Figures~\ref{fig:projectdocument} and~\ref{fig:platformdocument}, it is the
attribute's type, such as \texttt{Cutover}, \texttt{DurabilityClass} or
\texttt{Listener}. Most constraints test these enumerations
(Section~\ref{sec:enumdecision}).
