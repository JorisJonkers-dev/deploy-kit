\section{Domain Analysis}
\label{sec:domainanalysis}

The existing configuration covers one Kubernetes cluster, seven nodes, ten
namespaces, about thirty processes and twenty applications. It is maintained by
hand.

\subsection{Observations From the Existing Configuration}
\label{sec:observations}

\textbf{Repeated values.} One hostname appears seven times across three
repositories. Two tests check those copies for disagreement. A port appears in
the container specification, service, probe and monitoring rule.

\textbf{Repeated derivations.} Four deployments contain the same rollout block.
Comments explain that recreate leaves a period without a pod and a JVM needs
more startup time than a static bundle. A \emph{derivation} computes such values
from the authored model and cluster policy.

\textbf{Mechanisms instead of requirements.} The files specify rollout strategies
and node labels. They do not state whether an upgrade may interrupt service or
what a process needs from a machine. A volume that cannot attach twice requires
recreate. The error appears only when a second node is used.

\textbf{Shared values.} Hostnames must be unique. One process uses a graphics
card at a time. The \emph{edge} consists of shared entry points for external
traffic (Section~\ref{sec:sharedvalues}).

\subsection{Structural and Operational Concepts}

Structurally, a project groups applications. An application groups processes
released together. Processes offer and use named ports. Hostname paths lead to
an application's processes.

Operational concepts specify machine requirements, data durability, secret
access and delivery, health checks, startup time and whether versions may run
together during an upgrade.

\subsection{Notation}
\label{sec:notation}

The Task 0 feedback suggested ArchiMate or the C4 model instead of, or beside,
UML class diagrams.

A metamodel defines abstract syntax. Ecore implements EMOF classes, attributes,
references and multiplicities. Class diagrams show them directly. ArchiMate and
C4 describe systems.
