\subsection{A Third Metamodel for the Generated Files}
\label{sec:thirdmetamodel}

A third metamodel could support structural output checks, but a maintained copy
of the target schema could drift. It adds no constraint beyond the resolved
metamodel. Tests compare generated text with reviewed output and validate it
against target schemas. The resolved metamodel contains typed resource classes
(Section~\ref{sec:generatedresources}).

\subsection{Grammar First or Metamodel First}
\label{sec:grammarfirst}

The production implementation parses another serialisation of the source
language. If the Xtext grammar defined the language, the two syntaxes could
diverge. Both implementations instead check against the metamodel's exported,
machine-readable structure.

\subsection{One Resolved Model, or One Per Application}
\label{sec:oneresolved}

The resolved model covers all applications because edge routing, application
order and reverse dependencies require cluster-wide inputs. Separate
per-application computations could disagree or omit values.

Each repository receives a \emph{projection}: its application's part of the
resolved model, selected by filtering.
