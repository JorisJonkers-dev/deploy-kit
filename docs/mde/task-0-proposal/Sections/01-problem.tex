\section{Problem Statement}
\label{sec:problem}

A Kubernetes cluster typically runs a large number of services. Each service
needs a workload, service account, network policies, ingress routes, monitoring
rules and a disruption budget. These resources repeat the same facts in
different schemas. For example, a port appears in four files, while one
dependency sets both an address and an egress rule.

These facts are spread across several places. The path to one service can span
several repositories. Manually maintained copies can drift apart even when
each file is valid. The cluster accepts the files, but an application may no
longer reach its database or its metrics may not be collected.

Service dependencies also change over time. Changing one dependency currently
requires edits to every dependent service. A model can resolve dependencies
automatically and avoid these repeated edits. The dependency is changed once,
and every related service receives the new values. This project will generate
a consistent Kubernetes deployment set from one abstract application model.
